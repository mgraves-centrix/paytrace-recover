# Unguided merchant case test

Use the current PR build on a private/local server, not the older Azure deployment. Create a fictional paid-but-no-access case. Give the participant the case link, then read only this prompt: “You manage digital-course purchases. This customer paid but says they cannot open the course. Work out what you should do next, and keep them informed. Speak your thoughts aloud.” Do not explain the layout or point to controls. Do not use real customer or payment data.

Observe three tasks without prompting:

1. Find the next safe action and explain whether access can be changed yet.
2. Locate the payment, learner/course match, and lesson evidence supporting that decision. Ask what remains uncertain.
3. Set a customer update time and post a portal message. Ask whether the time itself sent an email and what the email status actually proves.

Record the time to the first correct action, navigation detours, misread evidence, hesitation before approval, missed overdue promises, and any point where the participant expects a notification that the product did not send. Afterward ask: “What would happen if you approved now?”, “How would you know the customer received your message?”, and “What would you do if verification failed?”

Pass criteria: the participant completes all three tasks without hints; never treats an AI recommendation as authorization; does not claim an access grant or email delivery before evidence confirms it; and can find the customer conversation within 15 seconds. If any criterion fails, record the exact screen/control and revise it before calling the case UX complete. Save only anonymized observations, not buyer records or session cookies.
