# Recovery intelligence lab

Open `/intelligence.html` from the merchant Focus workspace. The page requires an unlocked demo operator session or a verified admin/manager workspace. It adds five prototype capabilities without changing the existing payment, approval, or grant boundaries.

1. **PayPal purchase discovery:** Paused while sandbox PayPal credentials are shared across workspaces. The merchant route returns no reporting rows and does not call PayPal. A global Transaction Search response can contain another merchant's transaction identifiers, so an unlinked row cannot safely be shown or assigned. Use the merchant-bound demo checkout or registered trusted purchase intent instead. A future reporting feature needs credentials and transaction discovery scoped to the merchant before re-enabling it.
2. **Possible incident mode:** Three or more saved, completed sandbox captures for the same course with inactive access inside one 30-minute payment window raise a possible shared-incident signal. While that cluster is active, the automatic **grant** path pauses. AI investigation and manual case review remain available. Similar timing is not proof of a common cause.
3. **Autopilot rehearsal:** The merchant can change a hypothetical maximum purchase amount and daily cap and see which saved cases fit, need a model review, are held, already have access, or are samples. This uses saved records only. It sends no PayPal or course requests and creates no policy approval, reservation, or access write. A future actual run must reread both systems.
4. **Customer self-check:** From a private case session, a customer can request a rate-limited, read-only payment, entitlement, and protected-lesson check. Results explain missing access, payment review, a successful lesson check, or unavailable systems without exposing provider IDs or changing access. Case status is updated through the normal verification path, not by this customer request.
5. **Merchant evidence packet:** The merchant can download a JSON timeline of purchase checks, approval, access writes, verification, and customer contact events. Message text and email addresses are omitted. This is an internal preparation packet, **not** a PayPal dispute response or a submission to the Disputes API.

## Verification

Run `npm test`. The tests cover incident detection and grant pause, policy rehearsal without mutation, the disabled shared-account reporting route, private customer checking without a grant, merchant route access, and packet redaction. A completed buyer-to-lesson recovery still requires live sandbox acceptance. The public Azure sandbox demo includes this screen; that deployment does not itself prove a connected recovery.
